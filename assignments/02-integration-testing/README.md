# Лабораторная работа 2. Интеграционное тестирование

## 1. Название и цель задания

Проверить совместную работу импорта, хранилища SQLite, состояния списка и сохранения изображений. Отдельной ViewModel в приложении нет: список описан классом `ContactListState`.

## 2. Какие навыки проверяются

- Интеграционный тест с настоящей SQLite.
- Наблюдение транзакционности и отмены по фактическому коду.
- Разделение фильтра списка и поиска репозитория.
- Проверка кэша, который подключён не ко всем путям загрузки.

## 3. Что требуется реализовать или исследовать

Создайте `tests/IntegrationTests/Assignments`. Временная база — `TempSqlite`, признак `[Trait("Category", "Integration")]` — см. [docs/TESTING.md](../../docs/TESTING.md).

### 2.1. Импорт

Классы `ContactImportService` и `ImportCoordinator`. Файл `tests/IntegrationTests/Assignments/ContactImportTests.cs`.

Соберите сценарий: разрешение есть; источник отдаёт больше 1000 контактов; номера нормализуются ключом `NormalizeKey`; дубликат — тот же ключ, что у уже принятого или сохранённого номера; записи пишутся в SQLite. Отдельно проверьте повторный импорт, дубликаты внутри одного списка, пустой телефон, отказ в разрешении, исключение источника до записи и обрыв на одной из вставок. Посмотрите, откатываются ли уже вставленные строки и учитывается ли `CancellationToken`. Не подменяйте репозиторий списком в памяти там, где нужно увидеть файл SQLite. Обрыв вставки можно сделать обёрткой над `IContactStore`, которая бросает исключение на N-й записи и делегирует остальные вызовы реальному `ContactRepository`.

### 2.2. База и список

`ContactRepository` и `ContactListState`. Файл `tests/IntegrationTests/Assignments/ContactListStateTests.cs`.

Сохраните контакты и получите их обратно. Проверьте порядок, отсутствие отдельной сортировки, фильтр по имени, телефону и email, отсутствие фильтра по адресу, пустую базу и повторную загрузку без удвоения строк. Поиск `SearchContactsAsync` шире фильтра экрана: адрес участвует в поиске репозитория и не участвует в фильтре списка.

### 2.3. Изображения

`MemoryImageCache`, `ContactImageFileStore`, `UnsplashService.DownloadImageAsync`. Файл `tests/IntegrationTests/Assignments/ImageCacheTests.cs`.

Проверьте первое помещение в кэш, повторное добавление того же ключа, инвалидацию, очистку, запись файла, перезапись и удаление. Выясните, отправляет ли загрузка условные заголовки. Свойство `MemoryImageCache.SupportsValidators` фиксирует поддержку ETag и Last-Modified. Статический `ImageCacheService` в приложении разделяет один словарь на процесс; в тесте создавайте новый `MemoryImageCache`.

## 4. Как запустить приложение для выполнения задания

Для тестов приложение не нужно. Ручная проверка импорта на устройстве описана в [docs/RUNNING.md](../../docs/RUNNING.md) и [docs/ENVIRONMENTS.md](../../docs/ENVIRONMENTS.md). В Testing источник контактов фиктивный. Команда запуска приложения требует эмулятор или устройство.

## 5. Как запустить соответствующий тест

```bash
dotnet test tests/IntegrationTests/IntegrationTests.csproj --filter "FullyQualifiedName~ContactImportTests|FullyQualifiedName~ContactListStateTests|FullyQualifiedName~ImageCacheTests"
```

Команда `dotnet test` для IntegrationTests проверена. Фильтр без написанных классов не является сданным результатом.

## 6. Как проверить результат

- Импорт больше 1000 контактов оставляет в файле базы ожидаемое число строк.
- После исключения посередине импорта число строк совпадает с тем, что метод реально зафиксировал.
- Фильтр списка и поиск репозитория проверены разными утверждениями.
- Каталог изображений теста удалён.
- Повторы не зависят друг от друга.

## 7. Критерии успешного выполнения

- Методы задания помечены `Category=Integration`.
- Использован файл SQLite через `TempSqlite` и `ContactRepository`.
- Описаны дубликаты, повторный импорт, ошибка источника, частичный сбой и токен отмены.
- Есть проверка пустой базы и повторного чтения.
- Для изображений разделены память, файл и условные HTTP-заголовки.
- Тест не ходит в Unsplash и не читает контакты разработчика.
