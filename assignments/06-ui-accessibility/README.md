# Лабораторная работа 6. UI и доступность

## 1. Название и цель задания

Проверить интерфейс ContactFlow: узкий экран, планшет, длинные имена, крупный шрифт, TalkBack, подписи доступности и сообщения об ошибке сети. Автоматизируется контракт экранов. Проход по эмулятору готовится отдельно и без эмулятора не считается выполненным.

## 2. Какие навыки проверяются

- Сопоставление сценария с реальными подписями кнопок.
- Доступность элементов MAUI.
- Устойчивые селекторы `AutomationId`.
- Честная граница UI-автоматизации.

## 3. Что требуется реализовать или исследовать

Общие правила каталога `Assignments` и признака `Category` — [docs/TESTING.md](../../docs/TESTING.md). Идентификаторы автоматизации уже стоят на основных элементах. Их нельзя удалять.

### 6.1. Доступность и вёрстка

Каталог `tests/UITests/Assignments`. Файл `AccessibilityContractTests.cs`. На методы — `[Trait("Category", "UI")]`. Часть работы — правка `MainPage.xaml` и `ContactDetailPage.xaml` в `src/Phonebook`.

Добавьте в XAML:

- у кнопки импорта `SemanticProperties.Description="Импорт контактов с устройства"`;
- у кнопки «+» `SemanticProperties.Description="Добавить контакт"`;
- у «Сохранить» `SemanticProperties.Description="Сохранить контакт"`;
- у «Unsplash» `SemanticProperties.Description="Открыть поиск изображений"`.

Тест должен найти эти подписи, `LineBreakMode="TailTruncation"` у имени в списке и тексты «Не удалось загрузить изображения» и «Не удалось выполнить поиск» в `UnsplashImagePickerPage.xaml.cs`.

Отдельно на эмуляторе или устройстве, когда оно есть, проверьте ширину телефона, планшет, имя длиннее ширины экрана, масштаб шрифта 150% и 200% и TalkBack. Эти проверки не заменяются чтением XAML. Команды эмулятора в среде подготовки не выполнялись.

### 6.2. Сценарий интерфейса

Файл `tests/UITests/Assignments/ImportScenarioContractTests.cs`. На методы — `[Trait("Category", "UI")]`.

Реальный путь отличается от формулировки «Импорт из телефона» и «Найти фото»:

1. Открыть приложение.
2. Нажать кнопку с `AutomationId="ImportContactsButton"` (на экране это «📥»). Разрешение читает `MauiContactsPermissionGate` в Development. В Testing разрешение не спрашивается.
3. Импорт забирает все доступные контакты, отдельного выбора одного контакта телефона нет.
4. Открыть контакт в `ContactsCollection`.
5. Нажать «Unsplash» (`OpenUnsplashButton`), не «Найти фото».
6. Выбрать изображение и подтвердить диалог «Да».
7. Нажать «Сохранить» (`SaveContactButton`).
8. Убедиться, что контакт снова в списке.

Напишите тест, который сверяет эти идентификаторы и подписи с XAML. Тест эмулятора оставьте с `Skip`, пока нет Appium, образа Android и переменной `PHONEBOOK_RUN_UI=1`. Пропущенный тест не отчёт о пройденном сценарии.

## 4. Как запустить приложение для выполнения задания

Ручная проверка TalkBack и масштаба требует устройство и [docs/RUNNING.md](../../docs/RUNNING.md). Для фиктивных данных:

```bash
export PHONEBOOK_ENVIRONMENT=Testing
```

Запуск MAUI здесь не проверялся: нет workload `maui-android`.

## 5. Как запустить соответствующий тест

```bash
dotnet test tests/UITests/UITests.csproj --filter "FullyQualifiedName~AccessibilityContractTests|FullyQualifiedName~ImportScenarioContractTests"
dotnet test tests/UITests/UITests.csproj --filter Category=UI
```

Первая команда запускает классы задания. Вторая — все тесты с признаком `UI`, без инфраструктурного smoke. Пропущенный тест эмулятора виден как Skipped. Это не успешный E2E.

## 6. Как проверить результат

- В XAML есть четыре заданные семантические подписи.
- Контракт сценария не ищет надписи «Импорт из телефона» и «Найти фото».
- `dotnet test tests/UITests` не падает.
- В протоколе пропущенный эмуляторный тест не описан как пройденный.
- Ручная часть (6.1): приложите краткий отчёт `ui-manual-checklist.md` (или раздел в отчёте лабораторной): модель устройства или эмулятора, дата; масштаб шрифта 150% и 200% — видны ли подписи и обрезка длинного имени; TalkBack — озвучивается ли кнопка импорта по `Description`; без скриншотов с личными контактами. Если устройства не было — явно напишите «ручная часть не выполнялась».

## 7. Критерии успешного выполнения

- Семантические подписи добавлены указанным текстом.
- Контракт XAML и контракт сценария оформлены тестами с `Category=UI`.
- Длинное имя связано с уже существующим `TailTruncation`, а не с выдуманным переносом.
- Сообщения сетевой ошибки сверены с кодом страницы Unsplash.
- E2E на эмуляторе либо реально запущен, либо явно пропущен.
- Ручной чеклист сдан или помечен как невыполненный по причине отсутствия устройства.
